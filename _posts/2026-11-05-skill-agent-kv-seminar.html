## Retrieved Relevant Experience

### General Principles
- **Systematic Exploration**: Search every plausible surface or container exactly once before revisiting; prioritize unopened or unseen locations to cover the whole room methodically.
- **Immediate Acquisition**: As soon as a required object becomes visible and reachable, take it before moving elsewhere to avoid losing track or re-searching.
- **Destination First Policy**: After picking up a goal object, navigate directly to the known target receptacle and place it before resuming further search.
- **Track Counts & Progress**: Maintain an internal counter of how many goal objects are still needed; stop searching or terminate episode only when the counter reaches zero.
- **Use State-Changing Tools Early**: For tasks requiring heated/cooled/clean objects, acquire the object, then immediately use the nearest suitable appliance to change its state before any placement.
- **Establish Spatial Relations**: When a goal specifies a relation (under/inside/on), first locate the reference object, adjust its state if needed (e.g., turn lamp on), then search the specified spatial region for the target object or place it there.

### Clean Skills
- **Phase-Ordered Plan**: Always execute clean tasks in the fixed sequence: 1) locate & acquire target object, 2) bring it to an available water source/sink to clean, 3) navigate to final location, 4) place object.
  _Apply when: As soon as the goal specifies the object must be clean before placement._
- **Pick Before You Wander**: If the target object is visible or discovered, take it immediately; never leave it behind to explore other places, as possession enables direct cleaning and prevents redundant searches.
  _Apply when: After visually confirming the presence of the target object on any surface or inside an opened container._
- **Sink First for Cleaning**: Upon holding the target object, go straight to the nearest sink, basin, or faucet and issue the clean/use command before any placement attempts.
  _Apply when: Once the target object is in hand and its required state is ‘clean’._
- **Systematic Container Sweep**: When the object isn’t found on open surfaces, iterate through all unopened or unexamined containers in the room before revisiting already-checked spots to avoid search loops.
  _Apply when: After initial obvious surfaces are empty and the target object remains unfound._
- **State Verification Before Drop**: Always inspect or infer the object’s state after cleaning; if still not confirmed clean, re-clean before final placement to satisfy goal conditions.
  _Apply when: Immediately after a cleaning action and before placing the object at its target location._
- **Use Location Priors**: Begin search at the most probable category-specific surfaces (e.g., kitchenware on countertop/stove, food on dining table) to minimize exploration steps and avoid aimless roaming.
  _Apply when: At the very start of the task to choose the first search destination for the target object._

### Mistakes to Avoid
- **Don't**: Agent repeatedly revisits the same already-searched locations or containers instead of exploring new ones.
  **Instead**: Maintain an exploration map that records which rooms/containers have been fully inspected and prioritize unvisited or unopened candidates until all reasonable options are exhausted.
- **Don't**: Agent decides a closed container is empty without opening it, causing missed discoveries of target objects.
  **Instead**: Always open and inspect every plausible closed container at least once before ruling it out, using a checklist of unopened containers in the current room.
- **Don't**: Agent ignores or walks away from target objects that are already visible and reachable.
  **Instead**: Embed a perception buffer that immediately queues pick-up actions for visible goal objects and interrupts any ongoing exploratory loop.
- **Don't**: Agent keeps searching after acquiring enough items because it loses track of how many targets have been collected.
  **Instead**: Maintain explicit numerical goals and increment/decrement them on every successful pickup or placement, triggering transition to the next sub-goal when counts are satisfied.
- **Don't**: Agent fails to deliver a held target object to the known destination, instead continuing to wander.
  **Instead**: Adopt a hierarchical policy that, upon holding a goal object, immediately switches to a high-priority ‘deliver-to-goal’ subtask before resuming further search.

## General Principles
- **Systematic Exploration**: Search every plausible surface or container exactly once before revisiting; prioritize unopened or unseen locations to cover the whole room methodically.
  _When: Anytime the goal object count is not yet met and unexplored locations remain._
- **Immediate Acquisition**: As soon as a required object becomes visible and reachable, take it before moving elsewhere to avoid losing track or re-searching.
  _When: Upon first visual confirmation of a goal-relevant object._
- **Destination First Policy**: After picking up a goal object, navigate directly to the known target receptacle and place it before resuming further search.
  _When: Holding any goal object while its target location has been identified._
- **Track Counts & Progress**: Maintain an internal counter of how many goal objects are still needed; stop searching or terminate episode only when the counter reaches zero.
  _When: Throughout multi-instance tasks (e.g., “put two X…”)._
- **Use State-Changing Tools Early**: For tasks requiring heated/cooled/clean objects, acquire the object, then immediately use the nearest suitable appliance to change its state before any placement.
  _When: After picking up an object that must change temperature or cleanliness._
- **Establish Spatial Relations**: When a goal specifies a relation (under/inside/on), first locate the reference object, adjust its state if needed (e.g., turn lamp on), then search the specified spatial region for the target object or place it there.
  _When: Tasks containing spatial prepositions like under, inside, on, in_front_of._
- **Open Before Judging Empty**: Treat any closed container as unexplored; open it and inspect contents before deciding that the goal object is absent.
  _When: Encountering a closed drawer, cabinet, fridge, microwave, etc._
- **Avoid Redundant Rechecks**: Record which locations and containers have been fully inspected; do not revisit them unless new evidence suggests their contents changed.
  _When: After the first full pass of a location or when considering next search target._
- **Plan with Landmarks**: Continuously update and reference a map of known object and container locations to choose shortest paths and prevent aimless wandering.
  _When: Each time a new furniture piece, container, or goal object is observed._
- **Progressive Goal Decomposition**: Break tasks into ordered sub-goals: (1) locate object, (2) obtain or transform it, (3) locate destination/reference object, (4) satisfy spatial relation/placement, completing each sub-goal before moving to the next.
  _When: At the start of every episode and whenever the environment state invalidates the current sub-goal._
- **Efficient Relation Search**: When the goal pairs two objects (A under/on/inside B), restrict search for A to locations near B and vice-versa, instead of treating them independently.
  _When: On goals that mention both a target object and a reference object._
- **Terminate Only On Success**: Issue the 'done' action exclusively after validating that all goal conditions are met; otherwise continue searching or correcting object states.
  _When: Before ending an episode or when the agent believes the task is complete._

## Mistakes to Avoid
- **Don't**: Agent repeatedly revisits the same already-searched locations or containers instead of exploring new ones.
  **Instead**: Maintain an exploration map that records which rooms/containers have been fully inspected and prioritize unvisited or unopened candidates until all reasonable options are exhausted.
- **Don't**: Agent decides a closed container is empty without opening it, causing missed discoveries of target objects.
  **Instead**: Always open and inspect every plausible closed container at least once before ruling it out, using a checklist of unopened containers in the current room.
- **Don't**: Agent ignores or walks away from target objects that are already visible and reachable.
  **Instead**: Embed a perception buffer that immediately queues pick-up actions for visible goal objects and interrupts any ongoing exploratory loop.
- **Don't**: Agent keeps searching after acquiring enough items because it loses track of how many targets have been collected.
  **Instead**: Maintain explicit numerical goals and increment/decrement them on every successful pickup or placement, triggering transition to the next sub-goal when counts are satisfied.
- **Don't**: Agent fails to deliver a held target object to the known destination, instead continuing to wander.
  **Instead**: Adopt a hierarchical policy that, upon holding a goal object, immediately switches to a high-priority ‘deliver-to-goal’ subtask before resuming further search.
- **Don't**: Agent completes spatial placement while skipping required state changes (e.g., cleaning, heating).
  **Instead**: Integrate state precondition checks into the planner so that placement actions are only considered valid after verifying and, if necessary, executing the requisite state-changing operations.
- **Don't**: Agent repeatedly toggles or examines objects that yield no new information or progress.
  **Instead**: Implement novelty or information gain metrics that discourage repeating identical actions unless the environment state has changed since the last attempt.
- **Don't**: Agent mishandles spatial relations (e.g., ‘under’, ‘inside’, ‘behind’) by inspecting only obvious surfaces and ignoring less visible sub-locations.
  **Instead**: During task parsing, generate explicit search targets for all sub-locations associated with the reference object (drawers, shelves, underside) and iterate through them systematically.
- **Don't**: Agent forgets which object it is holding, leading to unnecessary pickups, drops, or misplacements.
  **Instead**: Maintain a dedicated ‘hand inventory’ structure updated after every pickup/drop, and consult it before issuing navigation or interaction commands.
- **Don't**: Agent executes inefficient action sequences by searching for each required object serially rather than batching placements or leveraging proximity.
  **Instead**: Use planning algorithms that group similar subtasks, allowing the agent to collect all required objects in one pass before performing consolidated delivery or transformation steps.
- **Don't**: Agent prematurely terminates or stalls without having observed any candidate objects that satisfy the goal.
  **Instead**: Only allow ‘done’ actions when explicit goal predicates are met; otherwise, continue targeted exploration of remaining unvisited rooms and containers.

## Clean Instructions
1. **Phase-Ordered Plan**: Always execute clean tasks in the fixed sequence: 1) locate & acquire target object, 2) bring it to an available water source/sink to clean, 3) navigate to final location, 4) place object.
2. **Pick Before You Wander**: If the target object is visible or discovered, take it immediately; never leave it behind to explore other places, as possession enables direct cleaning and prevents redundant searches.
3. **Sink First for Cleaning**: Upon holding the target object, go straight to the nearest sink, basin, or faucet and issue the clean/use command before any placement attempts.
4. **Systematic Container Sweep**: When the object isn’t found on open surfaces, iterate through all unopened or unexamined containers in the room before revisiting already-checked spots to avoid search loops.
5. **State Verification Before Drop**: Always inspect or infer the object’s state after cleaning; if still not confirmed clean, re-clean before final placement to satisfy goal conditions.
6. **Use Location Priors**: Begin search at the most probable category-specific surfaces (e.g., kitchenware on countertop/stove, food on dining table) to minimize exploration steps and avoid aimless roaming.

## General Principles
- **Systematic Exploration**: Search every plausible surface or container exactly once before revisiting; prioritize unopened or unseen locations to cover the whole room methodically.
  _When: Anytime the goal object count is not yet met and unexplored locations remain._
- **Immediate Acquisition**: As soon as a required object becomes visible and reachable, take it before moving elsewhere to avoid losing track or re-searching.
  _When: Upon first visual confirmation of a goal-relevant object._
- **Destination First Policy**: After picking up a goal object, navigate directly to the known target receptacle and place it before resuming further search.
  _When: Holding any goal object while its target location has been identified._
- **Track Counts & Progress**: Maintain an internal counter of how many goal objects are still needed; stop searching or terminate episode only when the counter reaches zero.
  _When: Throughout multi-instance tasks (e.g., “put two X…”)._
- **Use State-Changing Tools Early**: For tasks requiring heated/cooled/clean objects, acquire the object, then immediately use the nearest suitable appliance to change its state before any placement.
  _When: After picking up an object that must change temperature or cleanliness._
- **Establish Spatial Relations**: When a goal specifies a relation (under/inside/on), first locate the reference object, adjust its state if needed (e.g., turn lamp on), then search the specified spatial region for the target object or place it there.
  _When: Tasks containing spatial prepositions like under, inside, on, in_front_of._
- **Open Before Judging Empty**: Treat any closed container as unexplored; open it and inspect contents before deciding that the goal object is absent.
  _When: Encountering a closed drawer, cabinet, fridge, microwave, etc._
- **Avoid Redundant Rechecks**: Record which locations and containers have been fully inspected; do not revisit them unless new evidence suggests their contents changed.
  _When: After the first full pass of a location or when considering next search target._
- **Plan with Landmarks**: Continuously update and reference a map of known object and container locations to choose shortest paths and prevent aimless wandering.
  _When: Each time a new furniture piece, container, or goal object is observed._
- **Progressive Goal Decomposition**: Break tasks into ordered sub-goals: (1) locate object, (2) obtain or transform it, (3) locate destination/reference object, (4) satisfy spatial relation/placement, completing each sub-goal before moving to the next.
  _When: At the start of every episode and whenever the environment state invalidates the current sub-goal._
- **Efficient Relation Search**: When the goal pairs two objects (A under/on/inside B), restrict search for A to locations near B and vice-versa, instead of treating them independently.
  _When: On goals that mention both a target object and a reference object._
- **Terminate Only On Success**: Issue the 'done' action exclusively after validating that all goal conditions are met; otherwise continue searching or correcting object states.
  _When: Before ending an episode or when the agent believes the task is complete._

## Mistakes to Avoid
- **Don't**: Agent repeatedly revisits the same already-searched locations or containers instead of exploring new ones.
  **Instead**: Maintain an exploration map that records which rooms/containers have been fully inspected and prioritize unvisited or unopened candidates until all reasonable options are exhausted.
- **Don't**: Agent decides a closed container is empty without opening it, causing missed discoveries of target objects.
  **Instead**: Always open and inspect every plausible closed container at least once before ruling it out, using a checklist of unopened containers in the current room.
- **Don't**: Agent ignores or walks away from target objects that are already visible and reachable.
  **Instead**: Embed a perception buffer that immediately queues pick-up actions for visible goal objects and interrupts any ongoing exploratory loop.
- **Don't**: Agent keeps searching after acquiring enough items because it loses track of how many targets have been collected.
  **Instead**: Maintain explicit numerical goals and increment/decrement them on every successful pickup or placement, triggering transition to the next sub-goal when counts are satisfied.
- **Don't**: Agent fails to deliver a held target object to the known destination, instead continuing to wander.
  **Instead**: Adopt a hierarchical policy that, upon holding a goal object, immediately switches to a high-priority ‘deliver-to-goal’ subtask before resuming further search.
- **Don't**: Agent completes spatial placement while skipping required state changes (e.g., cleaning, heating).
  **Instead**: Integrate state precondition checks into the planner so that placement actions are only considered valid after verifying and, if necessary, executing the requisite state-changing operations.
- **Don't**: Agent repeatedly toggles or examines objects that yield no new information or progress.
  **Instead**: Implement novelty or information gain metrics that discourage repeating identical actions unless the environment state has changed since the last attempt.
- **Don't**: Agent mishandles spatial relations (e.g., ‘under’, ‘inside’, ‘behind’) by inspecting only obvious surfaces and ignoring less visible sub-locations.
  **Instead**: During task parsing, generate explicit search targets for all sub-locations associated with the reference object (drawers, shelves, underside) and iterate through them systematically.
- **Don't**: Agent forgets which object it is holding, leading to unnecessary pickups, drops, or misplacements.
  **Instead**: Maintain a dedicated ‘hand inventory’ structure updated after every pickup/drop, and consult it before issuing navigation or interaction commands.
- **Don't**: Agent executes inefficient action sequences by searching for each required object serially rather than batching placements or leveraging proximity.
  **Instead**: Use planning algorithms that group similar subtasks, allowing the agent to collect all required objects in one pass before performing consolidated delivery or transformation steps.
- **Don't**: Agent prematurely terminates or stalls without having observed any candidate objects that satisfy the goal.
  **Instead**: Only allow ‘done’ actions when explicit goal predicates are met; otherwise, continue targeted exploration of remaining unvisited rooms and containers.

  2. 청크의 KV를 원래 자리에서 새로 계산합니다. 이 값이 기준입니다.
  3. 같은 청크의 KV를 다른 문맥에서 계산합니다. 위치 정보(RoPE)는 원래 자리에 맞게 돌립니다.
  4. 두 KV의 차이를 잽니다 (K rel). 그리고 그 KV로 응답을 다시 채점합니다.
K rel
재사용한 K가 원래 K와 다른 정도를 원래 K의 크기로 나눈 값입니다. 0.15는 오차가 원래 크기의 15 %라는 뜻입니다. 층 28개와 KV 헤드 4개의 평균을 구하고, 표본 33개의 중앙값을 씁니다.
행동이 크게 바뀐 표본
각 모델이 대상 프롬프트에서 직접 뽑은 응답(temperature 0.4)을 그대로 두고, 행동 부분의 log 확률 합이 0.5보다 많이 바뀐 표본 수입니다. <action>…</action> 형식을 지키지 않은 응답은 틀린 출력으로 보고 세지 않습니다. 모델이 실제로 다른 행동을 골랐는지는 재지 않았습니다.

  • vLLM 0.11.0 한 버전, 게임 64개를 같은 걸음으로 돌린 조건입니다. 실제 서비스처럼 요청이 제각각 들어오는 조건이 아닙니다.

3 · 고민

3연구 질문에 대한 고민

지금 제 생각

제 연구 질문은 스킬 에이전트에서 KV 캐시를 더 많이 다시 쓰도록 스킬을 배치하는 방법(skill schema)을 설계하는 것입니다. 그런데 공통 부분을 앞으로 빼면 끝나는 문제라면, 연구 주제가 될 수 있는지 의문입니다.

그래서 두 가지를 생각합니다. 첫째, vLLM과 SGLang 같은 서빙 엔진의 특징을 근거로 KV 캐시를 더 잘 쓰는 방법을 찾는 것입니다 (RQ1). 둘째, 스킬 에이전트마다 상황과 프롬프트 구조가 다릅니다. ALFWorld에 맞춘 방법이 다른 곳에서는 맞지 않을 수 있습니다. 일반화를 할지, 벤치마크마다 해결책을 정리할지 고민입니다.
